Location and preferences

FreqBeacon can request device/browser geolocation to rank signals by reception plausibility. The browser mediates permission. Code in near-me.js stores latitude, longitude, a location label, accuracy, an update time and timezone in localStorage (signalScout:location:v1). Other radio preferences and receiver state may also be stored in the browser. Site-data clearing can remove local copies, but does not itself erase remote logs.

Network requests and external receivers

When the app requests schedules, receiver metadata, spectrum or SDR audio, requests may involve FreqBeacon's Cloudflare-hosted services, data providers and independently operated remote receivers. Those systems can receive normal connection information such as IP address, browser/network metadata, request time, receiver and tuning activity. External receiver operators set their own access rules and may keep their own logs.

Storage, logging, analytics and cookies

The app uses Cloudflare infrastructure and a D1 receiver-health database. Exact IP/log retention, any telemetry, cookie use (including receiver preference cookies), subprocessors and server-side coordinate retention require deployed configuration verification. This draft intentionally does not claim zero tracking, zero cookies or zero server retention.

Purpose and choice

Location and radio preferences are used for discovery, ranking, context and remote receiver selection; network and security information may support service reliability and abuse controls. You can deny location permission, use manual choices where provided, clear local storage and close any external receiver connection. Some capabilities may become less accurate or unavailable.
